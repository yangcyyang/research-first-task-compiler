# 先查再造 · 闸门工作流 Skill

面向复杂、多阶段任务的通用 Agent Skill。解决四个常见问题：

1. AI 输出过多，人需要阅读和审阅大量内容。
2. AI 早期方向偏差到交付才发现，造成大量返工。
3. 重新造轮子——不调研现有产品和开源项目就直接发明。
4. 方案没验证就承诺开发，实施时才发现不可行。

## 核心机制

```text
用户自然语言
→ 任务卡 → 方向闸门一
→ 调研与方案设计【调研门 · 条件触发】
→ 方案卡 → 方向闸门二
→ 【验证门 · 条件触发：证据账本有承重灰项才开】
→ 【执行打包 · 按需触发：派工/跨会话才出完整任务包】
→ 正式执行 + 自检
→ 结果卡 → 验收 → 基线
→ 后续轮次只看变化
```

## 三张卡

| 卡片 | 回答的问题 | 第一屏优先展示 |
|---|---|---|
| 任务卡 | 做什么 | 目标、产物、范围、非目标、待确认 |
| 方案卡 | 怎么做 | 结论、推荐方案、执行模型、风险、待确认 |
| 结果卡 | 做成了什么 | 完成情况、核心成果、差异、风险、待验收 |

## 四条全局纪律

1. **审阅预算**：每个第一屏 ≤5 结论、≤3 风险、≤3 决策，其余下沉。
2. **提升规则**：会改变决策的事实不许藏在第二、三层。
3. **条件门交代**：跳过调研门/验证门/执行打包必须写明理由。
4. **AI 叙事约束**：总概 → 拆分详解；按用户关注点排序；技术用语不上第一屏。

## 初始化一次运行目录

```bash
python scripts/new_run.py --name "园区报事报修后台梳理" --out ./runs
```

