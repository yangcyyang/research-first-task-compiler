# 工作流与产物规范

## 1. 标准阶段

| 阶段 | AI动作 | 人的动作 | 主要产物 |
|---|---|---|---|
| 用户输入 | 保留原始请求，提取意图 | 表达问题、背景、目标 | 原始输入 |
| 任务卡 | 结构化任务 | 确认目标、边界、核心模型、产物 | 第一屏 + 完整记录 |
| 方向闸门一 | 固化任务版本 | 确认、局部修正、查看明细或退回 | 已确认任务卡 |
| 调研与方案 | 分析资料、调研参考、形成方案 | 无需持续陪跑 | 调研底稿 |
| 方案卡 | 汇总推荐方案和取舍 | 确认路径、取舍和高风险事项 | 第一屏 + 完整记录 |
| 方向闸门二 | 冻结执行边界 | 确认、修改或退回 | 已确认方案卡 |
| 正式执行 | 处理全量信息、展开细节 | 仅处理升级问题 | 完整成果 |
| 自检 | 检查方向、完整性、来源、案例和一致性 | 无需逐项检查 | 验证报告 |
| 结果卡 | 汇总完成情况和风险 | 验收、局部返工或拒绝 | 第一屏 + 完整记录 |
| 基线 | 固化已接受事实、方案和决策 | 接受结果 | 基线记录 |
| 后续变更 | 与基线对比 | 只审新增、修改、删除、影响和待确认 | 变更摘要 |

## 2. 每张卡的双产物

### 对话产物

- 面向人的第一屏。
- 只包含当前阶段最重要的判断信息。
- 不是完整文档摘要，而是决策摘要。
- 用户只读这一屏也能决定：确认、修正、下钻或退回。

### Markdown 记录

- 面向 AI、审阅者和未来版本。
- 第一层保留第一屏快照。
- 第二层记录完整说明。
- 第三层记录证据、来源、假设、冲突和版本。
- 可以很完整，但不能默认要求人全文阅读。

## 3. 三张卡的职责边界

### 任务卡

只回答“做什么”，不要提前写成完整解决方案。

允许出现：

- 初步执行轮廓；
- 初步核心模型；
- 初步验收标准。

不应深入：

- 详细工具选型；
- 完整方案评分；
- 低层实现步骤；
- 大量页面或字段细节。

### 方案卡

只回答“怎么做”，不要把执行成果伪装成已完成。

允许出现：

- 调研结论；
- 替代方案；
- 执行模型；
- 预期成效；
- 风险和依赖。

不应宣称：

- 未实际执行的结果已经成立；
- 未验证的方案已经通过；
- 未确认的建议是业务事实。

### 结果卡

只回答“做成了什么”和“是否可接受”。

必须区分：

- 已完成；
- 部分完成；
- 未完成；
- 计划外变化；
- 风险和缺口；
- 需要验收的事项。

## 4. 进入下一阶段的条件

### 任务卡 → 方案卡

- 目标已确认；
- 范围与非目标已确认；
- 核心产物已确认；
- 关键歧义已解决或被显式延期；
- 任务卡版本被标记为 confirmed。

### 方案卡 → 正式执行

- 推荐路径或替代路径已选择；
- 核心取舍已确认；
- 执行边界已冻结；
- 高影响风险已知；
- 方案卡版本被标记为 confirmed。

### 结果卡 → 基线

- 必需产物已验收；
- 未完成项已被接受、延期或退回；
- 关键风险被接受或已处理；
- 结果卡版本被标记为 accepted。

## 5. 用户确认后的处理

用户确认第一层后：

1. 不要求继续阅读第二层。
2. 把第一层确认内容写入完整记录。
3. 将状态从 awaiting-confirmation 改为 confirmed。
4. 保存确认时间、版本和用户修正。
5. 进入下一阶段。
6. 如果用户后续发现第二层问题，只修正受影响部分并进行影响分析。
