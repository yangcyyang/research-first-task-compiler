# 任务卡｜第一屏

> 任务ID：TASK-001  
> 状态：awaiting-confirmation  
> 版本：0.1

## 一句话任务

从现有需求文档、会议纪要、字段表和旧系统截图中，梳理园区报事报修后台的一期业务模型、功能边界和关键页面。

## 目标

让物业运营人员能够完成工单受理、分派、处理跟踪、验收和关闭，并形成后续原型设计的稳定输入。

## 本轮产物

1. 角色与业务对象模型；
2. 主流程、状态机和关键异常；
3. 后台功能地图；
4. 一期页面清单；
5. 工单列表与详情页规格。

## 本轮范围

工单从提交到关闭的管理后台闭环。

## 明确不做

智能派单、维修绩效、库存管理和统计大屏。

## 核心模型初步判断

以“工单”为核心业务对象，以物业运营人员为主要后台用户。

## 主要风险或限制

资料对“维修完成后是否必须由报修人验收”存在冲突。

## 需要你确认

1. 一期是否包含用户验收？
2. 本轮是否只处理管理后台，不设计员工提交端？
3. 是否接受统计分析进入后续阶段？

## AI建议动作

确认上述三项后，进入开源项目、行业方法与具体方案调研。
