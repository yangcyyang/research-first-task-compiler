## 一句话结论

建议采用“资料事实化—领域建模—后台能力映射—页面规格—案例回归”的五阶段方案。

## AI推荐方案

推荐先建立结构化业务模型，再生成后台功能和页面，不直接从原始资料生成原型。

## 执行抽象模型

```text
原始资料
→ 有来源事实与冲突
→ 角色、对象、事件、状态、规则
→ 后台能力与页面
→ 关键页面规格
→ 业务案例回归
```

## 预期成效

降低方向偏差和后期返工，支持功能与原始依据之间的追溯，并让后续版本只审变化。

## 关键取舍

直接出页面更快；先建模多一步，但能显著减少“看起来像后台、实际不符合业务”的风险。

## 主要风险

资料版本冲突可能导致状态机和权限模型仍需人工决定。

## 需要你确认

1. 是否采用先建模后出页面的方案？
2. 是否用5个真实案例作为方向验收集？
3. 低风险页面细节是否允许AI采用可逆默认值？

## AI建议选择

三项均建议确认。
